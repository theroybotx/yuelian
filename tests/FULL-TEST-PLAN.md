# 约练网站全量验收测试计划

设计日期：2026-11-01（Asia/Shanghai）。本文件先于本轮测试执行编写；状态是测试设计，不是通过报告。

## 1. 验收目标与发布门槛

本轮验收对象是现有 Sites 网站、站内账号、Mac 上的约练后端、PostgreSQL 权限与事务，以及 DeepSeek 自然语言操作。必须先覆盖完整功能清单，再执行测试、修复缺陷、重新执行受影响检查，最后在待发布的同一代码版本完成全量回归。旧轮次的通过数量不可累加为本轮通过数量。

本轮必须修复并以可重复用例验证：退出的是约练站内账号，不退出 GPT；个人菜单只有清晰的个人中心和退出操作，没有重复的“账号与登录”；学员不显示教练或团队管理选项。数据库中的账号、成员关联和角色必须由后端决定。

本轮账号契约已经确定：以数据库保存的约练用户名和密码注册/登录；密码使用 scrypt；独立 cookie 和数据库会话，Sites/GPT 只保留为外层预览门禁，站内退出不改变它。注册只可选教练或学员；教练注册自动创建教学资料，学员无执教/团队入口。邀请必须指定已注册的约练用户名，由后台查账号后绑定，不能信任自填邮箱或前端 user_id。Mock 账号也在业务账号表中；只有已授权真实控制员可从固定列表进入 Mock，普通用户必须提供凭证。

发布门槛：下表所有适用的自动化用例及线上冒烟用例通过；无尚未修复的功能、安全或阻断性 UI 缺陷；测试报告保留失败、修复和重测证据。跳过、部分执行、仅检查文案，均不得冒充相应功能通过。外部平台或硬件不可用时应标记明确限制，不能宣称已通过真机、真实多方登录或外部支付。

每条用例的执行报告记录 `id`、展开的参数、预期、实际、状态、证据文件、执行时间、代码提交、数据库名。参数化用例要列出每个组合结果，不能只记父级测试通过。断言禁止仅检查 HTTP 200：写入检查数据库与双方视图；拒绝检查状态码、无写入和无泄漏。

## 2. 范围与非目标

### 本次现有网站范围

- 站内登录、退出、角色与教练关系选择；测试身份受服务端白名单控制。
- 主页、日程、学员、场地文字资料、常规开放时间及日期规则、收件箱、课时统计、我的训练、个人中心和使用说明。
- 邀请学员并绑定既有档案、邀请助教/管理员、撤回邀请、调整权限、停用成员。
- 17 类业务操作，共享手动草稿与模型草稿后的授权、事务执行、恢复和撤销逻辑。
- 模型单任务、多任务依赖、澄清、纠错、拒绝和失败处理。
- PostgreSQL RLS、签名桥接、请求校验、并发、缓存与跨账号隔离。

### 尚未实现的业务能力

当前代码不能作为微信小程序、Android/iOS/iPad 原生 App 已发布的证据。真实微信/手机号登录、短信验证、支付宝订阅支付、高德地图定位/当前位置、外部微信/短信/邮件通知、导出文件、录音转文字、完整小班创建和成员编辑均未接入本网站。测试其入口不存在、禁用或准确说明范围；这不等于测试上述功能成功。用户名/密码是本轮站内认证，未经验证的邮箱不作为身份或邀请授权凭据。

## 15. 执行顺序与已发现覆盖缺口

1. 先冻结本计划与角色/账号契约。设计阶段只读代码，不先跑测试再倒填计划。
2. 补测试入口和夹具，复现退出 GPT、重复账号菜单、学员团队入口问题；同类助教路由和迟到请求同时检查。
3. 修复产品代码，运行 U/W，再执行全部 I/R；各套件使用独立库/端口，不互相清空夹具。
4. 运行 B/V 的全角色页面矩阵与实际业务流程；不是仅打开页面截图。手动动作、邀请和收件箱必须有写入后的断言。
5. 执行 L；记录真实模型失败及修复，不用 stub 成功替代。随机性语义检查按预定义动作/目标/副作用断言，不要求逐字文案相同。
6. 全部修复后，同一最终代码版本执行完整回归并生成报告；修复导致基线改变时重跑相关套件，最后完成 DEP 全部项目。
7. 只在既有 Sites 发布后完成线上复核，再向用户汇报。不得把本计划的存在、旧版本通过或本地通过写成“已上线且全量通过”。

设计审查时发现的现状缺口：

- `profileMenu()`、`accountContent()`、`renderGate()` 仍直链 GPT 退出；需要新增独立站内会话并替换所有路径，不能仅改按钮文字。
- 个人菜单同时出现“账号与团队”“登录与账号”“退出登录”；需统一信息结构。
- `accountContent()` 无条件显示 `onboardingForms()`，使学员出现“我是教练/开始执教/加入团队”。
- 受限助教的头像菜单与 route 仅按粗角色 coach 分支，未与细分权限完全一致；需测试深链和菜单。
- 旧单元测试大部分基于历史 `data.js`/`operations.js`，当前 `workspace-client.js` 的会话、映射和序列化缺直接覆盖。
- 旧“17 类动作×两入口”主要为接口测试；本轮仍要补 UI 的实际按钮/表单与两方消息变化。
- 旧恢复测试、真实模型、角色浏览器和账号测试散落在 ignored `output/`，不能依靠手工顺序或过期端口/夹具重复执行；本轮应形成可维护运行入口与统一报告。
- 旧安全报告存在“部分验证”项（真实多用户、备份恢复、部分撤销/规则矩阵等），本轮不能未经执行直接升级为通过。备份恢复与异地容灾不属于已完成业务功能，若未测试须在报告保留限制。
