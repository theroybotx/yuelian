# 预约意图补充验收 v1.1

设计日期：2026-11-01。依据用户新增判断：这是办事平台；学员在明确当前关联教练的页面问“明晚有空吗”，或委托“帮我问教练能否约课”，应进入待确认预约，而不是要求重写成完整指令。明确“只查、先看看、别约”才属于只读。

本文件定义 24 条原创虚构语义回归与 6 条后台/UI验收。全部输入和预期在 `intent-v1.1.mjs`，先完成数据及独立评分器离线检查再执行真实模型。它是新需求补充集，不是原105条保留集，也不回写原150条历史成绩。运行记录见文末。

## 上下文合同

- 今天固定为 2026-11-01（中国时区）。本人学员为小林 `st-lin`；滨江 `v-river`、青山 `v-hill` 均是虚构测试场地。
- 默认角色为学员，服务端已选定当前教练，`currentCoachName="示例 · 周教练"`。该字段来自 RLS 范围内的当前教练显示名，不接受浏览器自报，不携带其他教练资料，也不自动切换教练。
- 教练名称不匹配、占位“某某”、泛称“别的/其他”、尚未确定当前教练时，先确认对象，不能投给当前教练凑数。
- “明晚”只能得到日期 2026-11-02；没有开始时间、时长、场地就保持 null，不能猜19点、一小时或沿用无关旧课。
- 预约理解只生成待确认草稿。缺字段先补；用户确认后才写入预约及对应教练收件箱，不表示教练已经接受，更不会扣课时。
- 当前17类动作没有独立空闲查询能力。只读请求应诚实说明限制、引导查看现有日程，不能伪造可约时段。此类测试通过只能叫“安全处理只读请求”，不能叫“已上线空闲查询”。

## 24条输入与预期

表中“待补”表示草稿对应字段必须为 null。“当前教练”始终为上述周教练，不从输入偷偷切到另一位。

| INTENT-02 | 明天下午方便上课吗？ | 本人预约草稿；11月2日；不把下午自动变15点 |
| INTENT-03 | 帮我问周教练明晚能不能约课。 | 本人预约草稿；11月2日；开始、时长、场地待补 |
| INTENT-04 | 帮我问周教练明晚七点到八点能否在滨江上课。 | 本人预约草稿；11月2日19:00；60分钟；滨江 |
| INTENT-05 | 问一下周教练周三晚上八点能不能练一小时。 | 本人预约草稿；11月4日20:00；60分钟；场地待补 |

| INTENT-07 | 明晚能练吗？ | 本人预约草稿；11月2日；虽选中过旧课，仍不借用旧时间、时长或场地 |
| INTENT-08 | 帮我问周教练能约一节课吗？ | 本人预约草稿；日期、开始、时长、场地均待补；“一节”不等于60分钟 |

| INTENT-13 | 只查周教练明晚的开放时间，不发预约。 | 只读能力说明；无预约 |
| INTENT-14 | 明晚有空吗？先别约，我只是想看看时间。 | 不因前半句生成预约；只读能力说明 |
| INTENT-15 | 把周教练明晚的空档列出来。 | 只读能力说明；不捏造19:00等可用时段 |
| INTENT-16 | 帮我问林教练明晚能不能约课。 | 目标不匹配，先选教练；不投给周教练 |
| INTENT-17 | 帮我问某某教练明晚能否约课。 | “某某”未确定，先选教练 |
| INTENT-18 | 帮我问别的教练明晚有没有课。 | 先选正确教练；不自动跨教练切换 |
| INTENT-19 | 找其他教练约明晚七点，不用切页面。 | 先选正确教练；不因给出时间而错投 |
| INTENT-20 | 明晚有空吗？（教练端） | 可询问对象或说明空闲查询限制；不能从名单猜学员并预约 |
| INTENT-21 | 明晚有空吗？（未提供当前教练上下文） | 先确定教练；不能声称已选周教练 |
| INTENT-22 | 今晚找个人随便拉拉，不是报教练课。 | 球友活动不伪装为教练课程 |
| INTENT-23 | 我俩一起上，给我和小宇约明晚七点。 | 多人课仍未支持；不能拆成两条单人课 |
| INTENT-24 | 朋友问我“明晚有空吗”，这只是转述，不要给我约课。 | 转述和否定不触发预约 |

评分器独立检查意图、本人ID、日期、开始时间、时长、场地、未知结束时间、步骤数量及没有执行回执。开始或时长不明时，结束时间必须空；两者明确时，end可空或为一致换算值，例如19:00加60分钟为20:00，不能填入矛盾时间。此规则在真实模型运行前固定，不把等价的确定换算判为编造。只读说明须与查询相关且不能凭空给出 HH:MM 时段；目标不匹配的说明须围绕选择教练/对象。模型请求只携带 input，不带这些答案、case ID 或标签。

## 6条后端与界面验收

| ID | 场景 | 必须检查 |
|---|---|---|
| INT-API-01 | 已关联学员短问生成预约 | currentCoachName来自服务端当前教练；草稿本人ID/日期正确；未知字段空；预约/消息/课时账本无提前写入 |
| INT-API-02 | 伪造或指定其他教练 | 客户端context中的教练名不覆盖服务端；跨教练ID/工作空间拒绝；“林教练”不能写到周教练；无越权模型上下文及业务写入 |
| INT-API-03 | 补齐后确认预约申请 | 填入明确时间、时长、场地；确认才生成一条pending预约和一条对应教练收件箱申请；本人可见申请；其他教练/学员不可见；账本不扣课时 |
| INT-API-04 | 教练处理及重复提交 | 教练同意/拒绝后，学员收到对应状态；重复确认不重复预约/消息；生成草稿本身不表示接受 |
| INT-API-05 | 缺字段或撤权时提交 | 开始时间/时长/场地仍空不能提交；候选期间权限撤销不能继续；失败无部分业务写入 |
| INT-UI-06 | 移动端完整流程 | 底部入口输入短句；向上展示预约草稿；当前教练明确；未知字段空且可点选；传统操作保留；用户确认后看双方收件箱，未确认不能出现成功回执 |

这些是集成测试合同，不因语义模型返回合法JSON就判通过。由主任务的真实后台、浏览器与发布复验提供证据。

## 与原150条的关系

原 `SEM-C01` 使用同一句“明晚有空吗”，但旧fixture没有 `currentCoachName`，旧需求把问句统一视为查询。新需求必须在“当前关联教练明确”的新上下文重新验收（INTENT-01），旧通过结果不能证明新交互正确。保留旧数据/答案/成绩，不偷偷改成预约后宣称旧测试全部通过；缺少新字段的旧上下文另由 INTENT-21 验证。

以下原案例需作为防回归对照，预期不变：C02明确“别约”、C03/C30球友匹配、C08多人课、C07修改已确认课、C15无对象“行吧”、C16不要确认、C29取消及不扣课时。其余149条原案例没有因本次积极理解预约意图而获得新增权限或自动执行授权。

运行：`node tests/semantic/run.mjs --supplemental=intent-v1.1` 仅dry run；加 `--live --mode=new --concurrency=3 --output=...` 才是真实模型。新补充集有单独数据和oracle摘要，不与原baseline混算准确率。

## 执行历史

首轮 `output/semantic-v1/intent-v1.1-final/results.json`：源码稳定，严格22/24，独立交互等价审查23/24，16次模型请求及8次前置处理，用量74238 tokens。10条预约问句全部通过，已知字段完整，未确定字段保持空。

INTENT-14只读说明引用了上下文真实规则“周二14:00至18:00”，原评分器把任何HH:MM都判为编造，产生误杀。已逐项核对输入规则和响应，另存 `intent-v1.1-first-interaction-review.json`，不修改原评分；该例最终为clarification，明确不生成预约。同时其前置标记错误显示booking-request，作为独立的否定识别缺陷反馈修复。

INTENT-15“把周教练明晚的空档列出来”被错误理解为另一位教练，要求重新选择，是真实实现问题。首轮失败保持不变；后续修复回归另存目录，不把首轮22/24改写成一次全部通过。

最终完整回归 `output/semantic-v1/intent-v1.1-final2/results.json`：24/24严格通过，源码稳定。14次真实模型请求，10次前置处理，65299 tokens；14/15修复后均由前置正确处理。原评分器未改，原首轮失败及独立审查保留。最终累积证据和源码边界见 `output/semantic-v1/FINAL-ACCEPTANCE-MANIFEST.json`。

发布前后台回归另发现“只看看甲教练……”被较短前缀截成“看甲教练”。仅修理解模块的最长前缀匹配后，现有INTENT-11..19范围回归9/9严格通过（3次模型、6次前置），证据 `intent-v1.1-read-prefix-regression/results.json`。原24及姓名13报告不改；新源码边界及追加9条记录在 `FINAL-ACCEPTANCE-MANIFEST-v2.json`。确切后台触发句及相关API回归由主任务另行验收。
