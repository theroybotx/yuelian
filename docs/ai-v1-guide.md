# 约练 AI 理解层第一版：使用指南与本轮改动

更新日期：2026-11-01。本文说明当前网页中的操作方式和能力边界；具体发布版本与测试结果以对应交付报告为准。

## 从哪里开始

登录约练后，各业务页面底部都有“约练 AI”输入框。输入需求，点击“生成操作”，系统会整理成待核对的操作清单。手机上会打开底部操作面板；关闭面板后可继续浏览原页面。

收件箱中，可处理的预约还保留一个针对该消息的输入框。在这里输入“可以，帮我确认这节课”，系统有明确的当前预约对象。在没有选中预约的主入口单独说“可以”，不会自动代表确认某一条预约。

生成结果、回答补充问题和点击“更新草稿”都不会执行业务变更。需要你检查表单，点击“确认保存”“提交预约申请”“发送约课提案”或“确认执行 N 项”等按钮，后端才会再次校验并执行。生成阶段会保存临时任务和审计记录，用于继续调整；不会因此创建课程、扣课时或发送消息。

学员已经选择当前关联教练时，可以直接说“明晚有空吗”或“帮我问这位教练明晚是否可以约课”。系统会先整理本人的预约申请草稿；没有具体几点、多久或哪个场地，就留给你在表单补齐。请核对面板里的“接收教练”，确认后申请才会进入这位教练的平台收件箱，等待教练处理。明确说“只查空档，先不要申请”则保持只读。点名其他教练或泛指“某某教练”时，需要先选择正确的已关联教练，系统不会替你切换，也不会将请求发送给当前不符的教练。

底部麦克风按钮当前只填入示例文字，不录音；本轮没有交付语音识别。

## 一句话可以安排多件事

例如：

> 添加新学员小宇，登记他已经购买的 10 课时，然后给他在滨江网球场约明天下午 3 点到 4 点，最后查一下余额。

系统应整理出建档、登记课时、约课、查询余额四项。后续操作引用这次准备新建的学员，不需要你先保存学员、再重新描述剩下的任务。使用已有学员时，请换成你名单里的姓名。

场地也可以同样处理：先添加一个场地，再给学员在该场地安排课程。地址、球场编号、室内或室外等普通字段缺失时，在对应表单补齐。新场地的定位仍需人工核对，AI 不会编造地址或地图坐标。

关联操作统一确认后执行；其中一项无法通过权限、时间冲突或业务规则校验时，不会留下前面已执行、后面未完成的半组业务变更。

## 继续调整：只改你指出的内容

结果面板里有“继续调整”输入框。你可以先用表单修改，再输入一句补充，点击“更新草稿”。

| 你的补充 | 应当发生的变化 |
|---|---|
| “第二项改成 90 分钟，其他不动” | 只修改第二项的时长，保留其他步骤和已经填写的内容。 |
| “开始时间往后挪半小时，其他不变” | 有唯一约课草稿或明确指向的步骤时，开始时间加 30 分钟。对象不明时先补问。 |
| “只改场地，换成青山，其他保留” | 唯一匹配已授权场地时换场地，保留日期、学员、时长和备注。 |
| “场地还没定，清空场地选择” | 清空可编辑的场地选择，等待补选；不会改动依赖前面新建场地的引用关系。 |
| “不要改时间，只把备注改成练反手” | 只改备注，保留日期和开始时间。 |

没有明确要求修改的备注、观察、反馈、目标等文字会保留原值，不重新润色。普通模型故障时，系统在核对当前权限后保留原草稿，便于再次尝试或直接修改表单。若权限或资料已变化，旧草稿会被清除，要求重新核对；权限后台无法核实时，会先关闭当前资料访问。

“继续调整”用于修改已经存在的步骤。要追加、删除或重排任务，或把某一步改为另一种业务操作，请关闭当前草稿，从底部入口重新描述完整需求。

## 同名、“他”和“老地方”怎样处理

系统先根据当前账号有权访问的资料，核对姓名、场地、当前选中的学员、课程或消息。名单里只有一个人，也不代表一句含糊的话必然指向他。

- **同名学员或同名场地：** 结果里会出现候选按钮。选择正确对象后继续，原需求中其余任务仍然保留。
- **“他／她”：** 可以承接当前明确选中的学员、单人课程、预约消息或本轮已经确认的对象；没有明确对象时先问清楚。
- **“老地方／还是原来那儿”：** 需要先知道是哪位学员，并找到其最近已完成课程的唯一场地。没有历史依据，或最近记录有多个可能场地，会要求补选。
- **“老时间”：** 只有明确要求沿用时间，并且存在可核对的历史课程，才可使用其开始时间。不会一起复制旧日期、时长、购课金额或共享状态。
- **场地简称：** 唯一的“青山”可以对应“青山网球场”。如果两个场地都能简称“青山”，需要你选择；“青山北场”不会被当成“青山”。

例如“给小王登记已购买的 2 课时，另外给小李明天在老地方约一小时”，如果系统询问历史课程对应谁，选“小李”后仍应保留小王的购课登记。继续选择场地时，也不需要重新输入整个需求。

不在名单里的姓名不会自动绑定到相似姓名。新增学员档案也不会自动关联其账号：学员需要注册约练账号，再接受教练发出的定向邀请，才会关联到已有档案。

## 哪些页面可以做什么

底部 AI 入口可以跨页面整理当前角色有权处理的任务；页面中的按钮、选择框和表单继续保留。

| 页面或入口 | 当前主要操作 |
|---|---|
| 主页、日程／我的课程 | 提交约课申请、发送教练提案、查看课程；教练记录已经完成的已确认单人课程，或纠正支持范围内的课程时长、备注。 |
| 收件箱 | 确认或拒绝当前可处理预约；将普通待处理消息标记为已处理。条件式同意会先补问。 |
| 学员 | 添加和修改档案、训练目标及下次重点；登记已经购买的课时、查看余额；管理账号邀请关联。 |
| 场地与开放时间 | 添加和修改场地资料、每周开放规则、常规开放日及转场时间；支持在表单中补齐或修改字段。 |
| 课时统计 | 查看当前教练的整体课程统计，或明确某位学员的统计。数值由授权课程记录计算。 |
| 我的训练（学员） | 记录和修改自己的自主练习，选择练习日期，并决定是否与当前教练共享。 |
| 回访草稿 | 明确要求保存或修改回访草稿。新增批量草稿只适用于“至少 21 天未到课、有余课且没有未来预约”的默认条件。不会发送到微信。 |
| 个人中心 | 当前账号、教练关联、团队与权限等管理入口；具体选项随角色和已授予权限显示。 |

以上包含 17 类 AI 业务操作。团队授权、账号邀请等仍通过对应管理界面操作，不能靠一句话绕过管理权限。

## 常见口语与业务边界

| 表达 | 当前理解原则 |
|---|---|
| “一个钟”“个半钟”“一刻钟” | 分别为 60、90、15 分钟，之后仍需通过课程时段和业务规则校验。 |
| “明天下午三点到四点” | 按中国时区换算具体日期，开始时间 15:00、时长 60 分钟。 |
| 学员在当前关联教练页面说“明晚有空吗”“能不能约” | 整理本人的预约草稿，缺少的时间、时长和场地留待补齐，确认后才进入教练收件箱。 |
| “只查空档，先不要发申请” | 保持只读，可在日程查看；不会生成预约申请。 |
| “约球” | 可能指朋友打球，也可能指教练课程；上下文不明确时先补问。 |
| “先记着，下次补”“这节还没上” | 不代表课程已完成，不会据此消课。 |
| “扣半节” | 没有明确实际时长或一节课的时长依据时，先询问，不直接当作 30 分钟。 |
| “充值 800 元” | 金额不等于 800 课时。当前不能支付或按价格自动换算，需要明确已经购买的课时数。 |
| “如果不下雨就确认” | 条件尚未满足时先补问，不直接接受预约。 |
| “发给所有学员的微信” | 说明暂不支持外发，不擅自改成保存草稿，也不把“所有人”换成默认回访候选名单。 |

## 共享与权限

AI 和传统表单共用后端权限规则。教练、管理员、助教的可操作范围取决于当前授权；学员只能处理与本人关联的资料。模型看到的是经过权限筛选、再提炼任务相关信息后的上下文，不具有绕过数据库权限查询其他教练或学员的能力。

自主练习默认仅本人可见，勾选共享后才对当前有权查看的教练开放。修改练习时，没有要求改共享状态，就保留原状态。教练的课后记录和发布给学员的反馈分别处理，发布前应核对表单中的共享或发布选项。

生成之后到确认之前，权限、相关资料版本、预约状态、余额或时段都可能变化。确认执行时后端会再次检查；草稿里显示了某个对象，不表示之后永远有权操作它。

## 本轮修复与改进

1. 加入服务端理解层，结合当前资料识别人名、场地、历史依据和多个任务，减少无关数据进入模型。
2. 保存待确认任务的原始需求、候选问题和已选对象，补答同名、人物或场地问题时保留原任务。
3. 将已有草稿的自然语言调整改为限定字段修改；保留未涉及的手工修正、文字、步骤和引用。
4. 修正“新学员”表达导致多任务被提前截成选人问题的情况；保留建档、购课、约课、余额查询之间的关联。
5. 修正模型把学员姓名放入错误字段导致改名未生效的问题，以及单个开放星期的字段兼容；增加场地唯一简称、方向边界和明确清空选择的处理。
6. 自主练习保留明确日期，编辑时保留未修改的旧日期，禁止记录未来练习；说明文字与实际共享状态一致。
7. 指定学员的统计保留筛选对象，包含其授权的单人课和参与的小班课，同一节课不会重复计算。
8. 修正模型失败后可能恢复已撤权旧草稿的界面问题；明确区分主动取消、等待超时和响应格式错误。
9. 明确外发、金额与课时、未完成课程和不支持任务的边界，并补充单元、接口、浏览器和真实模型回归用例。
10. 学员对当前关联教练的间接约课问句可以进入预约草稿；明确只读、指定其他教练和微信外发请求分别处理，不混淆接收对象和确认步骤。

## 当前限制

- 每次操作清单最多 **8 步**，超过后需要拆成多次请求。
- 一份清单在当前教练的资料范围内处理；涉及不同教练时，需要分别进入对应教练页面。显示名称用于核对当前接收人，不提供全平台教练搜索或身份匹配。
- 预约需补齐具体日期、开始时间、时长和场地；时长为 **15 至 240 分钟，以 15 分钟递增**。目前不能直接发送只有“明晚有空吗”的开放式聊天消息。
- 同一任务从首次整理起，可继续补充约 **15 分钟**；每份待确认草稿也有有效期。过期后需重新生成并核对。
- 一个任务最多 **12 轮**，包含首次整理。继续调整不能无限累积上下文。
- 主入口每次最多 1600 字，结果中的补充输入最多 500 字。长任务可分段处理，但不能跳过必要确认。
- 暂不支持支付、退款、取消已安排课程、自动外发微信／短信／邮件、完整的小班新建排课、多人费用分摊和多人逐人消课。已有小班参与记录可以用于授权范围内的统计。
- 第一版没有持久昵称学习、自动训练或生产 RAG 检索。模型仍可能理解错误，需要检查生成的对象、时间、共享状态和操作范围。
- 本指南描述网页版能力。网页版的浏览器测试不等于微信小程序、原生 Android／iOS／iPad 应用或真实手机键盘已经完成验收。

## 资料与测试结果如何阅读

本轮参考模型厂商、教学机构、场馆和网球产品的公开一手资料，来源及用途见[公开资料与数据来源](ai-v1-sources.md)。测试语句、人物、地址和业务数据均为原创虚构；未使用私人教练聊天记录，也没有将公开网页当成真实用户训练数据。

交付报告应分别列出单元测试、真实数据库接口测试、使用受控接口的浏览器测试、连接真实数据库的浏览器测试和真实模型语义测试。它们验证的问题不同，不能把一种测试的通过数量当成另一种测试的结论。

固定语义评测是开发验收样本，不代表市场整体理解准确率。根据保留集失败修复后再次执行，应称为“修复后保留集回归”。运行中源码发生变化的旧结果需要注明，最终发布以冻结版本的检查结果和发布后复核为准。
