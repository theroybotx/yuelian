补充口语研究：公开页面支持的沟通模式主要是先问有无空、再确认人/场/时间，以及已约好后调整。没有找到可合法直接复用、质量可核验的中国大陆独立教练私人约课聊天集。本轮不伪造“采集了真实聊天”的结论；所有测试短句均原创。新增 30 条日常约球组，加上指代、修订及其他口语，共 78 条明确标记的口语案例，例如省略时间地点、语音同音错字、否定、向后挪半小时、只改一项、查询与预约的区别。

2026-11-01用户进一步明确：约练是办事平台。在已选定当前关联教练的学员页面，“明晚有空吗”及“帮我问周教练能不能约课”应生成待确认预约草稿，缺少的时间、时长和场地继续补齐；“只查有哪些可约时间、先看看别约”才保持只读。其他教练、未知对象或球友活动不能默认转成当前教练的预约。该规则来自用户的产品决定，不冒称是外部网站统一规则。新建独立24条 `tests/semantic/intent-v1.1.mjs` 验收，保留原150条旧上下文与历史成绩。

## 资料使用边界

1. 以上为语义和架构资料，不是可直接训练的真实交易或对话数据集。
2. 未复制长文、课程价格表、取消时限、退款比例或联系信息进入提示和测试数据。不同机构的具体规定不适用于约练。
3. 不自动加入雨天取消、收费、退款、消息外发等尚未实现的能力；请求涉及这些能力时，需要明确说明当前范围。
4. 约练的角色权限、课时账本规则、默认回访条件和支持操作，取自本项目当前代码及用户已经确定的产品规则，不取自外部机构。
5. 开发示例与评测样本全部重新创作，人物、地址、ID、课程、余额均为虚构；不将其声称为真实教练的自然语言数据。固定语料位于 `tests/semantic/dataset.mjs`。10 条开发示例位于 `tests/semantic/dev-examples.json`，当前未接入生产检索，不声称已实现 RAG 或自动学习昵称。

## 测试数据隔离

固定 150 条原创中文场景，45 条开发集、105 条保留测试集。每条记录输入、上下文及独立期望；开发示例只允许从 45 条开发集里选择，不读取 holdout 的期望值。运行器传给模型的对象只包含请求和授权范围内的虚构业务上下文，不包含 case ID、分组、标签或标准答案。

语料覆盖已支持的 17 类动作、人物/场地指代、同名和简称歧义、多任务依赖、否定、局部修改、缺失字段、越权和暂不支持的业务。所有结果以本地固定 oracle 比较，不能因为返回了合法 JSON 就算理解正确。

这是一套开发验收样本，不是市场整体准确率估计。若因保留集失败修改实现，该组后续结果应称为“修复后保留集回归”，不得继续把其当成完全未见样本。
